# My Orchestrate

必要な仕事だけを子へ渡し、親は設計・判断・統合を担当する。小さな修正や、親がその場で完結できる確認は直接処理する。作業量だけを理由に分担しない。

## 分担を選ぶ

次のどちらかに当てはまる仕事を委譲する。

- 対象と完了条件が明確で、親の作業と並行して進められる独立した仕事。
- 設計の不確実性や変更の影響が大きく、独立した評価に価値がある仕事。

必要な役割だけを起動する。並列数は独立した仕事の数と利用可能な枠に合わせる。以下は`task_name`と依頼文で表す役割であり、登録済みのカスタムエージェント名を前提にしない。

## 役割とモデル

| 役割 | model | reasoning_effort | 渡す仕事 |
|---|---|---|---|
| explorer | `gpt-5.6-luna` | `max` | 読み取り中心のコード探索、事実収集、影響範囲・関連テストの特定 |
| worker | `gpt-5.6-luna` | `max` | 合意済み仕様の局所的な実装、単純修正、文書化・下書き、差分整理・コミット準備 |
| reviewer | `gpt-6-astra` | `high` | 設計前の前提・案の批判、または実装後の仕様適合・回帰・検証不足の独立評価 |

- explorerや簡単なworkerの仕事は、Luna / maxを明示する。maxをlowへ節約目的で下げない。
- 複雑な設計・実装はまず親が判断する。切り出せる難しい実装を委譲する場合だけ、workerをAstra / highへ変更し、その理由を短く説明する。
- reviewerには「設計批判」か「実装検証」の目的を指定する。毎回両方を起動せず、両方が必要なら各段階で別の評価を行う。実装者自身を独立検証者として扱わない。
- commit準備だけのために常設の子を作らない。まとまった差分整理が必要な場合にworkerへ渡す。実際のcommit・push等は元のユーザー依頼の範囲に従う。
- ユーザーが別のモデルや推論設定を指定した場合は、その指定を優先する。

## 起動と受け渡し

`spawn_agent`では`model`、`reasoning_effort`、`fork_turns`を明示する。原則`fork_turns: "none"`とし、会話履歴の代わりに必要な情報を依頼文へまとめる。

```json
{
  "task_name": "explorer_tests",
  "model": "gpt-5.6-luna",
  "reasoning_effort": "max",
  "fork_turns": "none",
  "message": "目的、対象パス、必要な背景、制約、完了条件、返してほしい情報を記す。再委譲は行わず、指定範囲を担当する。"
}
```

- 各依頼には目的、必要な背景、対象ファイル、読み取り専用か編集可能か、完了条件を含める。編集担当の範囲を重複させない。
- 子の返答は結論、根拠のパス・行番号、実施した変更・検証、未解決点を中心にする。長い全文転載は必要な場合に限る。
- 明示的な履歴引き継ぎ要求がある場合は、ツールが対応する最小限の履歴を渡す。全履歴forkはモデル上書きと両立しない環境があるため、利用中のツール仕様を確認する。
- 指定モデル・推論設定が使えない場合、無言で別モデルへ置き換えない。制約を伝え、親で対応できる範囲を進める。

## 実行中と待機

親は子と重複しない作業を進める。子の結果が次の判断に必要になったら待つ。

`wait_agent`は設定済みの長い既定待機時間を使う。既定値が短い、または明示指定が必要な場合は、上位指示とツールの許容範囲内で長い値を指定する。短いwaitの連打や、`list_agents`を使った代替ポーリングを避ける。完了・メッセージ通知は期限より早く返るため、固定sleepで待機を代替しない。

タイムアウト時は、失敗と決めつけず、必要な場合に進捗を一度確認して次の行動を選ぶ。子への追加依頼も差分と必要な背景だけを渡す。

## 統合とモデル報告

結果を受け取った親は、重要な根拠と変更箇所を確認して統合する。子の仕事を最初からやり直さず、矛盾や不足がある部分だけ追加確認する。

実行した子について、役割・モデル・reasoning・forkを最終報告に短く添える。起動要求と実行確認を区別する。

- 実行モデルを確認する場合は、その子に対応する実行メタデータや`turn_context.model` / `effort`を一度照合する。別タスクのログや子の自己申告を実測の代わりにしない。
- 実行メタデータが参照できない場合は「指定: Luna / max、実行値: 未確認」のように記す。確認できたと装わない。
- 例：`explorer_tests: Luna / max、fork=none（実行モデル・effortをログで確認）`。
